# ViPlay durable decisions

Update this file only when a decision changes. New entry format: `DNN · YYYY-MM-DD · decision — rationale`.

## Active decisions

- **D01 · 2026-08-17 · FFmpeg is not bundled.** Installation and updates remain managed by the user/system; the app searches `PATH`, plus `/opt/homebrew/bin` and `/usr/local/bin` on macOS. Superseded by: D27
- **D02 · 2026-08-17 · Split uses stream-copy.** This avoids quality loss and long encoding times; the split may move to the nearest suitable keyframe.
- **D03 · 2026-08-17 · Split output keeps the source container extension.** Both parts are written to a temporary directory beside the source and moved to final names after success.
- **D04 · 2026-08-17 · Contact sheets use an FFmpeg filter chain.** `ffprobe` supplies duration; `fps`, `scale`, `pad`, and `tile` are the required filters.
- **D05 · 2026-08-17 · `drawtext` is optional.** Some FFmpeg distributions omit it; timestamps are skipped and the contact sheet still succeeds.
- **D06 · 2026-08-17 · FFmpeg errors must be actionable.** Missing dependencies include platform install commands; operation stderr is capped at 800 characters and shown in a wrapping UI surface.
- **D07 · 2026-08-17 · The pure Go decoder remains only for thumbnails.** User-triggered split and contact-sheet operations belong to FFmpeg.
- **D08 · 2026-08-17 · Tests and a Wails build are required after every completed code change.** Sandbox runs use `/private/tmp/viplay-go-build` as the Go cache.
- **D09 · 2026-08-17 · English is the default and fallback application locale.** The initial release supports English and Turkish, and the selected locale persists between sessions.
- **D10 · 2026-08-17 · Every feature must ship with English and Turkish UI copy.** `locales/catalogs.json` is the single source for frontend and backend strings and is embedded in the Go binary. Vue loads its active catalog from Wails before mounting. Additional languages are added only in that shared file.
- **D11 · 2026-08-17 · Repository prose is English-only.** Markdown, code comments, identifiers, and developer documentation remain English even when user instructions are Turkish; Turkish is valid inside translation catalogs.
- **D12 · 2026-08-18 · Deletion prefers the native macOS Trash and falls back to permanent removal.** Files on mounted volumes use that volume's `.Trashes` directory when available; unsupported or read-only Trash locations must not prevent deletion.
- **D13 · 2026-08-18 · Multi-split uses one FFmpeg segment operation for all markers.** Outputs retain the source container, use stream-copy, and follow the existing nearest-keyframe behavior without quality loss.
- **D14 · 2026-08-19 · ViPlay terminates when its last window closes on macOS.** ViPlay is a single-window application, so closing the main window with Command-W must not leave a headless process running.
- **D15 · 2026-08-19 · Re-encoding offers only locally available, more efficient codecs.** Superseded by: D25
- **D16 · 2026-08-19 · Playlist thumbnails are generated by a controlled sequential queue.** Superseded by: D19
- **D17 · 2026-08-19 · CI builds the ignored frontend output before invoking Wails packaging.** Binding generation loads the Go package and therefore requires the embedded `frontend/dist` path to exist; Linux packages use Wails' default GTK4/WebKitGTK 6 stack, while Windows packaging installs NSIS explicitly.
- **D18 · 2026-08-19 · MPG and FLV use cached MP4 playback proxies.** Superseded by: D21
- **D19 · 2026-08-20 · Playlist thumbnail generation prioritizes the active neighborhood, auto-pauses during video playback, caps initial directory auto-generation, yields CPU cooperatively, removes deleted file thumbnails from cache, and ignores deletions in queue watchers.** Large directories previously saturated CPU decoding and caused DOM animation thrashing and playback stutter. Ordering from the active video outward, auto-pausing on playback, capping initial auto-generation to a 30-item window, yielding 15ms between items, removing cached thumbnails on file deletion, and avoiding re-triggers when removing items ensures smooth playback, clean caches, and a responsive interface.
- **D20 · 2026-09-16 · Seeking pauses playback during scrub and step-seek sequences.** Rapid seeking and timeline scrubbing while playing previously caused audio stuttering, excessive decoder contention, and dropped frames. Pausing playback immediately upon seek initiation, ignoring stale timeupdates during seeking, batching frame seeks with requestAnimationFrame, keeping thumbnail generation paused during seek bursts, and resuming playback once seeking settles preserves system performance and responsive scrubbing.
- **D21 · 2026-09-16 · MPG, FLV, and AVI use cached MP4 playback proxies.** Superseded by: D23
- **D22 · 2026-09-16 · Re-encoding supports real-time progress reporting and cooperative cancellation.** Transcoding can be a long-running CPU-intensive task. Parsing FFmpeg's `-progress pipe:1` standard output in real-time exposes progress percentage, encoding speed, FPS, and timestamps to the frontend. ViPlay provides cancellation controls in the notification surface and topbar, terminating the running FFmpeg process via Go context cancellation, deleting temporary output files, and leaving the original source file untouched.
- **D23 · 2026-09-16 · MPG, FLV, AVI, WMV, and MKV use fast cached MP4 playback proxies with stream-copy acceleration.** WebView / WebKit does not natively support legacy formats (MPG, FLV, AVI, WMV) or arbitrary Matroska (MKV) codec configurations (e.g. AC3/DTS audio, 10-bit color, or non-WebM containers). ViPlay automatically prepares an MP4 compatibility proxy in cache. When the video stream is already H.264 or HEVC 8-bit, video frames are copied directly (`-c:v copy`) and only audio is converted to AAC, generating proxies in under a second while preserving 100% video quality. If `<video>` errors on any media file, ViPlay falls back to on-demand proxy generation. Superseded by: D26
- **D24 · 2026-09-16 · Main window drag regions and OS file drop are explicitly handled.** With hidden native titlebars, `--wails-draggable: drag` and `-webkit-app-region: drag` designate `.topbar`, `.sidebar .brand`, and empty states as window drag handles while interactive elements remain non-draggable. Enabling `EnableFileDrop` and hooking `events.Common.WindowFilesDropped` allows users to drop video/audio files or folders directly onto the window to open them immediately.
- **D25 · 2026-09-16 · Re-encoding supports MP4 (H.264) and optional trashing of original media.** ViPlay offers an MP4 (H.264/AAC) transcode profile for non-H.264/non-MP4 video files to ensure universal playback and device compatibility, alongside HEVC and AV1. Moving the original source file to the macOS Trash upon successful transcode is now optional via a user-facing checkbox (persisted in local preferences). When the original is preserved, strict file size reduction is not mandated, allowing format conversions even when the resulting MP4 is slightly larger, and the newly created file is inserted alongside the original in the playlist.
- **D26 · 2026-10-25 · Playback proxies remux whenever possible, encode in hardware otherwise, and stay within a bounded cache.** Any proxied container is remuxed when video is 8-bit H.264 or 8/10-bit HEVC (tagged `hvc1`, which WebKit requires), and AAC audio is copied instead of re-encoded. Other video uses `h264_videotoolbox` on macOS with libx264 as fallback. Proxy creation locks per output file so one long conversion does not block other files, and the cache evicts least recently used proxies above 20 GB. Media probing and proxy preparation run concurrently, and FFmpeg encoder/filter listings are cached per binary path. On macOS, D28 replaces proxies with libmpv; proxies remain the Windows/Linux path.
- **D27 · 2026-10-25 · macOS packages bundle FFmpeg, ffprobe, and libmpv; Windows and Linux keep system FFmpeg.** `build/darwin/bundle_media.py` copies Homebrew's `ffmpeg`, `ffprobe`, and every non-system dylib they and the app load into `ViPlay.app`, rewrites load paths to `@executable_path/../Frameworks`, records each component's version, SPDX license, and source archive, and raises `LSMinimumSystemVersion` to the newest `minos` of any bundled binary. `requireMediaTool` prefers binaries next to the executable before `PATH`. ViPlay is GPL-3.0-or-later, which is compatible with the GPL-3.0-or-later FFmpeg build and GPL-2.0-or-later mpv. Tagged releases publish the corresponding source of every bundled component (upstream archive, resources, external patches, and formula) collected by `build/darwin/fetch_sources.py`. `ProbeMedia` falls back to ffprobe for containers the pure Go MP4 reader cannot parse.
- **D28 · 2026-10-25 · macOS playback uses libmpv beneath a transparent webview.** WebKit cannot open many containers and codecs (MKV, AVI, WMV, 10-bit HEVC, AC3/DTS), which forced slow proxies. libmpv renders through its OpenGL render API into an `NSOpenGLView` placed below the `WKWebView`; the webview is made transparent with the private `drawsBackground` key because Wails beta.34 does so only under the `private_mac_apis` build tag, which rules out the Mac App Store. The HTML controls stay unchanged: `frontend/src/nativePlayer.js` mirrors the `HTMLVideoElement` subset `App.vue` uses, `video-margin-ratio-*` confines the picture to the uncovered stage, and every load and subtitle path passes the media authorization check. Windows (`wid` child window) and Linux (render API; X11 `wid` does not cover Wayland) remain HTML5 until implemented.
